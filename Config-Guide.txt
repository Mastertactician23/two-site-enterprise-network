 *** BEFORE CABLING THE SERIAL LINK ***
 The 2901 has no serial port out of the box. On each router:
   1. Click the router, open the Physical tab
   2. Switch the power OFF (the toggle on the chassis image)
   3. Drag an HWIC-2T module into an empty slot
   4. Switch the power back ON
 Only then will Serial0/0/0 exist.

===============================================================================
 SECTION 4 - TWO RULES THAT WILL SAVE YOU HOURS
===============================================================================

 RULE 1: THE 3560 NEEDS AN ENCAPSULATION COMMAND
 -----------------------------------------------
 On a 3560, this ALWAYS comes before "switchport mode trunk":

     switchport trunk encapsulation dot1q

 Without it you get:
     Command rejected: An interface whose trunk encapsulation is "Auto"
     can not be configured to "trunk" mode.

 The 2960 does NOT accept this command - it is dot1q only. So:
     3560 (MLS-*)  -> include the encapsulation line
     2960 (SW-*)   -> leave it out

 RULE 2: TURN ON SYNCHRONOUS LOGGING FIRST
 -----------------------------------------
 Log messages will interrupt your typing and silently corrupt commands.
 The very first thing you configure on every device:

     line console 0
      logging synchronous
      exec-timeout 0 0

 This reprints whatever you were typing after each message. Without it you
 will type a correct command and watch it fail for no visible reason.

===============================================================================
 PHASE 3 - TRUNKS
===============================================================================

 Order: multilayer switches first, then access switches. You will see
 native VLAN mismatch warnings between doing one end and the other.
 That is expected and it stops once both ends match.

-------------------------------------------------------------------------------
 3a - MLS-HQ1
-------------------------------------------------------------------------------
configure terminal
interface range fastEthernet0/1-3
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,30,99
 no shutdown
exit
interface gigabitEthernet0/2
 description To MLS-HQ2
 switchport trunk encapsulation dot1q
 switchport mode trunk
 switchport trunk native vlan 999
 switchport trunk allowed vlan 10,20,30,99,100

===============================================================================
 PHASE 4 - STP ROOT PLACEMENT
===============================================================================

 Splitting the root across the pair means both uplinks carry traffic
 instead of one sitting idle.

--- MLS-HQ1 ---
configure terminal
spanning-tree vlan 10,99 root primary
spanning-tree vlan 20,30 root secondary
end

--- MLS-HQ2 ---
configure terminal
spanning-tree vlan 20,30 root primary
spanning-tree vlan 10,99 root secondary
end

--- MLS-BR1 ---
configure terminal
spanning-tree vlan 10,99 root primary
spanning-tree vlan 20,30 root secondary
end

--- MLS-BR2 ---
configure terminal
spanning-tree vlan 20,30 root primary
spanning-tree vlan 10,99 root secondary
end    

>>> CHECKPOINT 4
>>>   show spanning-tree vlan 10   -> MLS-HQ1 says "This bridge is the root"
>>>   show spanning-tree vlan 20   -> MLS-HQ2 says "This bridge is the root"
>>> On an access switch, show spanning-tree vlan 10 - one uplink FWD, one BLK.
>>> That blocked port is your redundancy. It is correct, not a fault.

 ABOUT THE CLOCK RATE
 --------------------
 Only the DCE end needs "clock rate". Check which end you have:
     show controllers serial 0/0/0
 Look for "DCE" or "DTE" in the first few lines. Put the clock rate on
 whichever router reports DCE. If neither has it, the line stays down.

 network 172.16.10.0 0.0.0.255 area 0
 network 172.16.20.0 0.0.0.255 area 0
 network 172.16.30.0 0.0.0.255 area 0
 network 172.16.99.0 0.0.0.255 area 0
 network 10.2.2.4 0.0.0.3 area 0
 network 10.2.2.8 0.0.0.3 area 0
end

 WHY "passive-interface default"?
 It stops OSPF sending hellos out of user VLANs, where there is no router
 to talk to. The two "no passive-interface" lines re-enable it only on the
 uplink to the router and the transit link to the peer core switch.

 PHASE 12 - REDUNDANCY AND FAILOVER TESTS
===============================================================================

 Record before and after output for each. These results are what turn a
 configuration exercise into a tested design.

 TEST 1 - HSRP GATEWAY FAILOVER
   1. show standby brief on MLS-HQ1  (Active for VLAN 10)
   2. From an HR PC, start: ping 172.16.10.100 -t
      (in PT, use Desktop > Command Prompt, ping -t)
   3. On MLS-HQ1:  configure terminal / interface vlan10 / shutdown
   4. Expect a few dropped replies, then recovery
   5. show standby brief on MLS-HQ2 - now Active for group 10
   6. On MLS-HQ1:  no shutdown
   7. Preempt returns Active to MLS-HQ1 automatically
   RESULT TO RECORD: number of packets lost during failover

 TEST 2 - CORE SWITCH FAILURE
   1. Continuous ping running from an HR PC
   2. Power off MLS-HQ1 completely (Physical tab, power switch)
   3. Traffic reroutes: HSRP moves, STP unblocks the second uplink,
      OSPF withdraws the routes through MLS-HQ1
   4. Power it back on and watch everything return
   RESULT TO RECORD: total outage duration

 TEST 3 - STP REDUNDANCY
   1. On SW-HQ1: show spanning-tree vlan 10
      Note which uplink is FWD and which is BLK
   2. Shut the forwarding uplink
   3. The blocked port transitions to forwarding
   4. show spanning-tree vlan 10 again to confirm
   RESULT TO RECORD: which port took over, and how long it took

 TEST 4 - OSPF PATH FAILURE
   1. From an HR PC: tracert 172.16.10.100 - note the path
   2. Shut MLS-HQ1 Gig0/1 (its link to R-HQ)
   3. show ip ospf neighbor on R-HQ - adjacency drops
   4. tracert again - the path now goes via MLS-HQ2
   RESULT TO RECORD: both traceroute outputs, side by side

 TEST 5 - WAN LINK FAILURE
   1. Shut R-HQ Serial0/0/0
   2. Inter-site pings fail, intra-site pings keep working
   3. show ip route on either router - the far site's routes are gone
   4. Restore and watch OSPF re-converge
   RESULT TO RECORD: what still worked while the WAN was down
   NOTE: this is the one single point of failure in the design. Naming it
   honestly is better than pretending it is not there.

 TEST 6 - BPDU GUARD
   1. Connect a spare 2960 to SW-HQ1 Fa0/5
   2. The port goes err-disabled within seconds
   3. show interfaces status err-disabled
   4. Recover: interface fa0/5 / shutdown / no shutdown

===============================================================================
 TROUBLESHOOTING - SYMPTOM TO CAUSE
===============================================================================

 "Command rejected: An interface whose trunk encapsulation is Auto..."
   -> You are on a 3560 and forgot: switchport trunk encapsulation dot1q

 %CDP-4-NATIVE_VLAN_MISMATCH
   -> One end of the trunk is on native VLAN 1. Configure the other end.
      Harmless warning, but fix it - it means untagged frames land wrong.

 %SPANTREE-2-BLOCK_PVID_LOCAL
   -> Same cause, but STP is now blocking the link. Must be fixed.

 HSRP group stuck in INIT
   -> The SVI is down. An SVI only comes up when at least one access port
      in that VLAN is up. Check the VLAN exists and a PC is connected.

 Both switches Active for the same HSRP group
   -> They cannot see each other. Check the trunk between them carries
      that VLAN in its allowed list.

 OSPF neighbour stuck in EXSTART
   -> MTU mismatch, or duplicate router-id. Check both.

 OSPF adjacency never forms
   -> Wrong wildcard mask in a network statement, or you made the
      interface passive. Check: show ip ospf interface

 PC gets 169.254.x.x
   -> DHCP failed. Check ip helper-address on the SVI, that the pool
      exists on the router, and that the router is reachable.

 PC gets an address but cannot reach anything
   -> The pool's default-router is probably wrong. It must be the HSRP
      virtual IP.

 Serial link stays down
   -> No clock rate on the DCE end. show controllers serial 0/0/0

 Inter-VLAN routing does not work on a 3560
   -> "ip routing" was never entered. It is off by default.

 Ping fails the first time then succeeds
   -> Normal. That is ARP resolving. Ping twice before believing a failure.


===============================================================================
 WHAT THIS DESIGN DOES NOT INCLUDE, AND WHY
===============================================================================

 EtherChannel / LACP
   The topology uses single links between devices. Adding EtherChannel is
   a reasonable extension, but do it LAST, on the MLS-to-MLS link only,
   and only after saving a working file. In Packet Tracer the "allowed
   vlan" list does not always propagate from member ports to the
   auto-created Port-channel interface, which silently suspends the
   members. If you add it, set the trunk config explicitly on BOTH the
   member range AND the port-channel interface, then confirm with
   "show running-config" that the two blocks match exactly.

 Firewall / DMZ
   No ASA in this topology. Segmentation here is by VLAN and, if you add
   them, by ACL on the multilayer switches.

 Internet edge
   Both sites are private. Adding an ISP router and NAT on R-HQ is a
   natural next extension.

 HSRP interface tracking
   Supported on the 3560 in most PT builds. If "standby 10 track ..." is
   rejected on your image, leave it out and note it - priority and
   preemption still give you working failover.
